1. 项目概述
做一个深圳专用的工资实时计算器。用户可以输入税前工资或税后工资，选择深圳医保档位、公积金个人缴纳方式、班制，然后实时看到自己“已经赚了多少钱”。金额按 月、天、小时 三个维度增长，并带有摸鱼小按钮、下班倒计时、迷你悬浮窗等趣味功能。

核心目标
税前模式：输入税前工资，自动算五险一金个人部分、个税、税后到手，再进入实时工资计算。

税后模式：直接输入税后到手，不反推、不算五险一金、不算个税，直接进入实时工资计算。

根据班制实时计算当月已赚、今日已赚、当前小时已赚。

当月已赚自动补发：用户月中打开，也自动把当月 1 号到昨天的工资补上。

启动时展示温馨提示页，用户确认后进入主界面。

界面现代、有趣、有动画，不像传统财务软件。

所有政策参数可配置，政策变化后用户可自行更新。

完全离线，所有数据存本地 JSON。

非目标（一期不做）
不做多城市切换。

不做加班费计算。

不做年终奖单独计税。

不做法定节假日调休精确计算。

不做云端同步、账号系统。

不做复杂日历实际计薪模式（可作为二期高级选项）。

不做联网更新检查。

2.2 关于数据库与联网的说明
结论：用本地 JSON 文件，不用数据库，不联网。

理由：

数据量极小：整个 app 只有一份用户配置 + 一份摸鱼历史，JSON 完全够用。

JSON 天然可读可备份：出问题时让用户把文件发给你就能排查。

零依赖：System.Text.Json 是 .NET 内置的，不需要安装数据库引擎。

完全离线：不发起任何网络请求，不检查更新，不上传任何数据。

小 app 不需要数据库：SQLite 虽然也能用，但对这个场景是杀鸡用牛刀。

4. 功能需求
4.1 两种模式与简化设计
应用支持两种模式，两种模式的输入复杂度完全不同：

模式一：税前模式（精细模式）
用户输入税前月薪，系统计算五险一金个人部分、个税、税后到手。

用户可输入/选择的内容：

养老保险

方式 A：按深圳标准自动（系统用内置参数计算）

方式 B：选择基数档位（下限 / 实际工资 / 上限 / 自定义基数）

方式 C：直接输入个人月缴额

医疗保险

档位：一档 / 二档

方式 A：按深圳标准自动

方式 B：选择基数（下限 / 实际工资 / 上限 / 自定义基数）

方式 C：直接输入个人月缴额

失业保险

方式 A：按深圳标准自动

方式 B：选择基数或直接输入个人月缴额

公积金

方式 A：直接输入个人月缴额

方式 B：输入基数 + 比例

方式 C：输入基数 + 比例 + 上限（系统先钳制基数再计算）

其他扣款（可选）

用户可自行添加其他固定扣款项目（如企业年金、补充医疗等），填写名称和金额。

个税相关

当前月份（用于累计预扣）

专项附加扣除（可选，默认 0）

模式二：税后模式（极简模式）
用户输入税后到手，不反推税前、不算五险一金、不算个税。

设计意图：有些用户懒得输入五险一金和个税参数，他只知道自己每个月固定到手多少钱。对这类用户，税后模式就是“我就填一个数，然后直接开始看钱增长”。

用户只需要输入：

税后月到手金额

班制

不需要输入：

税前工资

医保档位

公积金

个税参数

当前月份

专项附加扣除

输入完成后，直接进入实时工资计算流程。

4.2 五险一金计算（仅税前模式）
深圳个人缴纳部分：

项目	个人比例	缴费基数下限	缴费基数上限
养老保险	8%	4775 元	27549 元
医疗保险一档	2%	6727 元	33633 元
医疗保险二档	0.5%	6727 元	33633 元
失业保险	0.2%	2520 元	44265 元
公积金	5%～12% 或自定义	按公司规定	按公司规定
以上为示例值，必须做成可配置。

缴费基数规则：

text
缴费基数 = clamp(税前工资, 基数下限, 基数上限)
个人缴纳额 = 缴费基数 × 个人比例
灵活性要求：每个险种都支持三种输入方式，用户可自由切换。

4.3 个税计算（仅税前模式）
使用 累计预扣法。

公式：

text
累计应纳税所得额 = 累计税前收入
                  - 累计减除费用（5000 × 当前月份）
                  - 累计五险一金个人部分
                  - 累计专项附加扣除

本期应预扣预缴税额 = 累计应纳税所得额 × 预扣率 - 速算扣除数 - 累计已预扣预缴税额
预扣率表：

级数	累计应纳税所得额	预扣率	速算扣除数
1	≤ 36000	3%	0
2	36000～144000	10%	2520
3	144000～300000	20%	16920
4	300000～420000	25%	31920
5	420000～660000	30%	52920
6	660000～960000	35%	85920
7	> 960000	45%	181920
一期假设用户每月工资相同，系统自动计算 1 月到当前月的累计，得出当前月个税。

4.4 班制设置
支持预设和自定义。

预设：

五天八小时双休：9:00–18:00，午休 12:00–13:00。

大小周：大周双休，小周单休。

六天工作制：周一至周六。

每日十小时：9:00–20:00，午休 1 小时。

自定义：

上班时间、下班时间。

午休段，可添加多个。

每周工作日，勾选周一到周日。

大小周循环设置。

每日计薪小时，默认 8。

重要说明：节假日统一不计算工资，系统强制休息，不含节假日工资及加班费。

4.5 实时工资引擎
计算秒薪：

text
日薪 = 税后月薪 / 月计薪天数（默认 21.75）
秒薪 = 日薪 / 每日计薪小时 / 3600
默认使用固定折算模式。二期可加“日历实际模式”。

实时显示三个维度：

本月已赚：大数字，实时增长。

今日已赚：中数字，实时增长。

当前小时已赚：小数字，从整点开始累计。

当月已赚自动补发：

用户第一次打开时：

取当月 1 号到昨天。

遍历每一天，如果是用户设置的工作日，加一个完整日薪。

今天再按当前时间计算已赚。

如果当前时间在上班前，今日已赚为 0。

如果在午休，只算上午已工作部分。

如果在下班后，今日已赚为完整日薪。

状态判断：

当前时间	状态	今日已赚
上班前	未开工	0
上午工作中	赚钱中	已工作秒数 × 秒薪
午休中	休息中	上午已工作秒数 × 秒薪
下午工作中	赚钱中	(上午 + 下午已工作秒数) × 秒薪
下班后	已下班	完整日薪
非工作日	强制休息	0

8. 验收标准
税前模式输入 20000，医保一档，公积金 5%，能算出五险一金个人部分和个税。

税后模式只输入税后金额和班制，直接进入实时计算，不弹五险一金和个税。

五险一金每个险种都支持“自动 / 基数 / 金额”三种输入方式切换。

公积金支持“直接填金额 / 基数+比例 / 基数+比例+上限”三种方式。

修改任何参数，弹出确认框，确认后计时重置。

上班时间数字增长，午休暂停，下班停止。

当月已赚自动补发 1 号到昨天的工资。

摸鱼按钮能计时并显示消耗金额，摸鱼记录能存本地并查看。

启动时先展示温馨提示页，确认后进主界面，可勾选不再显示。

迷你悬浮窗置顶、可拖拽、透明度可调、位置记忆。

界面在 1366×768 和 1920×1080 下正常。

无未处理异常，退出后配置能恢复。

关于页面包含深圳专用说明、Lee老师邮箱、温馨提示。

全程无网络请求，无数据库依赖，仅读写本地 JSON。

JSON 文件损坏时能自动回退备份并提示，不崩溃。

9.4 打包命令
bash
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:PublishTrimmed=true
输出为一个独立的 .exe 文件，双击即可运行，无需安装 .NET 运行时。

这份方案书可以直接作为 AI 开发的输入。建议你先把“第 0 章”和“第 3 章”发给 AI，让它先做设计系统；确认样式满意后，再逐步让它做计算、实时引擎和页面。
